# 设计说明

本文说明形式化的整体结构、若干必须作出的设计决定，以及它们与定稿的对应关系。

---

## 一、"语法 / 证明系统 / 语义" 三层，以及 `Semantics.lean` 是什么

形式化分三层，正好对应三个模块：

| 层 | 问题 | 模块 | 内容 |
|---|---|---|---|
| **语法**（syntax） | 语言里**有哪些式子**？ | `EvidenceLogic/Core/Syntax.lean` | `Form`：变元、原子谓词、`¬ ∧ ∨ →`、`∀ ∃`、`⊳`、`⊲`；自由变元 `FreeIn`；代入 `subst`／`inst`；单项上下文 `Ctx` |
| **证明系统**（proof system） | 由哪些式子**能推出**哪些式子？ | `EvidenceLogic/System/Derivable.lean` | 归纳关系 `Derivable`：E、S1、S2、F1–F4、R1、P1、P2 |
| **语义**（semantics） | 式子**在什么结构里为真**？ | `EvidenceLogic/Model/Semantics.lean` | `PSet`、`Base`、`Entails`、`Frame`、`IsModel` |

**「语义」就是把符号解释成数学对象**，从而能谈论"真"：

* 语法只规定 `t ⊳ φ` 是一串符号；语义规定它**在什么条件下成立**——
  例如本项目取「支持者的真值蕴含被支持命题的真值」等条件；
* 有了语义才有**模型**（`Frame` + `IsModel`）、**有效**（`Frame.Valid`）、
  **后承**（`Entails`，即"在所有结构中有效"）这些概念；
* 因此 `Semantics.lean` 不是"证明系统的注释"，而是**独立的一层**：
  `Soundness.lean` 正是连接两层的桥——「可推导 ⟹ 有效」。

一句话：**语法管"写得对不对"，证明系统管"推得出推不出"，语义管"真不真"。**
本项目两者都建，并用可靠性定理把它们连起来。

### `Semantics.lean` 内部又分两层

`⊢`（经典后承）与 `⊳`／`⊲`（背书关系）需要的语义并不相同，故设两层：

**(1) 经典基语义 `Base`（用来定义 `⊢`）**
基结构把 `⊳`、`⊲` 当作**普通二元关系符号**，解释成**真值层面**的函数

```
suppI, refutI : PSet W → PSet W → PSet W
```

即关系只依赖两个**真值**、不依赖子公式的语法——这正是经典逻辑把 `t ⊳ φ`
视为原子公式的做法。它使代入引理成立：

```
B.truth (subst σ φ) ρ = B.truth φ (fun y => B.truth (σ y) ρ)
```

于是经典后承定义为"在所有基结构中有效"：

```lean
def Entails (p q : Form) : Prop :=
  ∀ (B : Base) (ρ : Nat → PSet B.W), B.truth p ρ ≤ B.truth q ρ
```

`Entails` 含一切经典一阶有效式（代入、量词实例化、重言式、爆炸律等），
因此定稿 S1／S2／E 里的 `p ⊢ q`、`φ ⊣⊢ ψ` 都在此得到解释。

**(2) 背书语义 `Frame` + 模型类 `IsModel`**
`Frame` 把 `⊳`、`⊲` 解释为**语法索引的**关系

```
supp, refut : PSet W → Form → (Nat → PSet W) → Prop
```

（第二个自变量是**公式本身**）。`IsModel M` 的每个字段恰好是定稿一条规则的
语义闭包条件：

| 字段 | 对应规则 |
|---|---|
| `nonempty` | 状态空间非空（否则一切命题坍缩为一个） |
| `classical` | 经典后承在模型内成立（连接 `⊢` 与模型真值） |
| `agree` | 真值只依赖自由变元（标准一阶语义相合性） |
| `e` | **E** 经典等价替换 |
| `s1`／`s2` | **S1**／**S2** |
| `f1`／`f2`／`f3`／`f4` | **F1**／**F2**／**F3**／**F4** |
| `r1` | **R1** |
| `p1`／`p2` | **P1**／**P2** |

## 二、语言：单排序语法（公式即项）

定稿规定 `t ⊳ φ` 中的 `t` 是**项**，且"公式可编码为项"，因此本项目采用
**单排序语法**：只有一个语法范畴 `Form`，公式直接充当项。于是

* `a ∧ b`（F3／P1 的合取支持者）就是 `Form.and a b`；
* `∀x p`（F2／P2 的全称支持者）就是 `Form.all x p`；
* `c ⊲ d`（嵌套关系）就是 `Form.refut c d`。

好处：F1–F4、P1、P2 中"同一主体""全称主体""合取主体"等表述无需额外的
编码／解码函数，"嵌套只能向上构建"在语法层面直接可见。

## 三、为什么语义中的关系必须**语法索引**

若让 `⊳` 的解释只依赖两个真值（即 `suppI : PSet → PSet → PSet`），
则 P1 会退化为平凡条件：P1 的结论是 `(a ∧ b) R ((c ∧ d) S f)`，
而 `(c ∧ d) S f` 若只按真值解释，在前提 `(c ∧ d) S f` 成立时其真值恒为 `⊤`，
于是 P1 只在要求 `R (…) ⊤` 成立——与 `S`、`f` 无关。

因此背书语义中关系以**公式**为第二自变量（`supp : PSet W → Form → … → Prop`）。
但这样一来**经典基**必须反过来只依赖真值（见上节），否则代入引理
（`subst` 与真值交换）不成立。两层分别是"语法索引"与"真值索引"，
正是这个互补关系使整套系统自洽。

## 四、为什么模型类要求状态空间非空

关系子公式的真值在本语义中是**恒常命题**（要么 `⊤` 要么 `⊥`）。
若状态空间 `W` 为空，则所有命题都相等，`⟨fun _ => P⟩ = ⊤` 对任意 `P` 成立，
无法从"关系公式有效"取出"关系成立"。故 `IsModel` 含 `nonempty : Nonempty M.W`，
典范模型族 `Canon.isModel` 也相应要求 `[Nonempty W]`。

## 五、F1／F2／P2：自由变元即全称概括

定稿把 F1／F2／P2 写作「`∀x (t R p(x)) ⇒ t R ∀x p(x)」这样带 `∀x` 的形式。
在 Hilbert 型系统中，带自由变元的推导读作"对任意赋值成立"，因此形式化时
这三条规则以**开公式的推导**为前提：

* **F1**：由 `t R φ` 得 `t R ∀x φ`，副作用条件 `x ∉ FV(t)`；
* **F2**：由 `p R φ` 得 `(∀x p) R φ`，副作用条件 `x ∉ FV(φ)`；
* **P2**：由 `a R c` 与 `(∀x c) S f` 得 `(∀x a) R ((∀x c) S f)`，副作用条件 `x ∉ FV(f)`。

这与 `IsModel.f1/f2/p2` 的形状一致（前提对**所有**赋值成立）。若照字面把
`∀x (t R φ)` 当作前提公式，它本身几乎不可推导（系统没有对证据公式的概括规则），
规则将形同虚设——这是该约定的必要性所在。

## 六、元规则 E 的载体

E 允许在任何位置以经典等价互相替换。形式化用**单项上下文**：

```lean
inductive Ctx | hole | atom … | not … | all … | suppL … | suppR … | refutR …
def Replace (φ ψ γ δ : Form) : Prop := ∃ C : Ctx, γ = C.plug φ ∧ δ = C.plug ψ
```

可靠性证明中：洞在 `⊳`／`⊲` 的**第二个**自变量（被支持／被反驳的公式）时用
`IsModel.e`；洞在**第一个**自变量（支持者）时只需真值同余。

## 七、与定稿的逐条对应

| 定稿 | 形式化位置 |
|---|---|
| 一、语言（`⊳`／`⊲` 独立原语、可嵌套） | `Syntax.Form`、`Form.supp`／`Form.refut` |
| 二、元规则 **E** | `Ctx`／`Replace` + `Derivable.e` + `IsModel.e` |
| 三、**S1**／**S2** | `Derivable.s1`／`.s2`、`IsModel.s1`／`s2` |
| 四、**F1**–**F4**（对 `R ∈ {⊳,⊲}`） | `Derivable.f1`–`.f4`（`Kind` 统一两种关系）、`IsModel.f1`–`f4` |
| 五、**R1** | `Derivable.r1`、`IsModel.r1` |
| 六、**P1**／**P2**（`R,S` 各 4 种组合） | `Derivable.p1`／`.p2`（`kR kS : Kind`）、`IsModel.p1`／`p2` |
| 七、明确不包含的规则 | 构造子中确实不存在；第十节结果说明其不可推导 |
| 八、系统性质 | `Properties.lean`（部分）+ `NonDerivable` 反模型 |
| 九、主要可导出结果 | `Derived.lean` |
| 十、不能推出的典型命题 | `NonDerivable.lean` |

## 八、实现注记

* **自足记号层**：Lean 4 核心只提供 `LE`／`≤`，`⊤ ⊥ ⊓ ⊔ ᶜ` 在 Mathlib 中；
  为保持零依赖，`EvidenceLogic/Core/Prelude.lean` 自行声明同名类型类与记法。
* **嵌套归纳类型与 mutual**：`Form` 的参数列表是 `List Form`（嵌套归纳）。
  若递归直接进入列表元素，Lean 会退化为良基递归，等式只是命题性的；
  故 `truth` 与 `truths`（以及代入、不变性引理）写成 **mutual 块**保持结构递归，
  证明中才能直接用 `rfl`／`show`。
* 本 Lean 版本中**文档注释不能紧邻 `mutual`**（解析错误），需用普通注释；
  且 Lean 的块注释**嵌套**，注释正文里不能出现字面 `/-`（否则会多开一层、报 `unterminated comment`）。
* **`mutual` 递归里要显式给隐式公式参数**：在复合形状上 `NoRel`／`truth` 之类的谓词**不是**
  定义性可归约的，递归调用必须写成 `f atomRel (φ := φ) h.1 ρ` 这种显式形式，否则合一失败。
* **`Frame.truth` 与 `Base.truth` 不是定义性相等**：`M.truth φ ρ` 与
  `(Canon.base M.W M.atomRel).truth φ ρ` 的 `rfl` **失败**（两者分别读 `Frame.supp` 与 `Base.suppI`
  两个字段）；只有**典范框架**才有 `Canon.frame_truth` 这条**命题性**等式。
  这条事实是"为什么某些结论只能对典范框架陈述"（例如受限 `E` 片段的不变量，见
  [`讨论与局限.md`](讨论与局限.md) 第 7 节）的直接机制，`EFree`／`NormalForm` 等模块都受它约束。
* **记法优先级陷阱**：`⊣⊢` 是 `infix:20` 而 `→` 是 `25`，故
  `(u ⊳ v) ⊣⊢ (u' ⊳ v') → …` 会被解析成 `(u ⊳ v) ⊣⊢ ((u' ⊳ v') → …)`（报 `type expected`）；
  写定理陈述时必须给等价式**加括号**：`((u ⊳ v) ⊣⊢ (u' ⊳ v')) → …`。
* **`PSet` 实例不透明性的实用解法**（本轮踩出并落地）：`PSet` 的 `⊓`／`⊔`／`ᶜ` 等实例带
  `@[implicit_reducible]`，核在默认透明度下不展开，故 `(a ⊓ b).holds w` 不会自动看成
  `a.holds w ∧ b.holds w`。**不要改 `Semantics.lean`**——在需要的文件里加展开引理即可，
  而且 `Iff.rfl` 会被接受：

  ```lean
  @[simp] theorem PSet.holds_inf (a b : PSet W) (w : W) :
      (a ⊓ b).holds w ↔ a.holds w ∧ b.holds w := Iff.rfl
  -- _sup / _compl / _top / _bot 同型
  ```

  随后统一用 `congrFun (congrArg PSet.holds h) w` 取逐点等式，再 `rw [PSet.holds_inf, …] at h`
  化成显式 `∧`／`∨`，最后 `Iff.intro (Eq.mp h) (Eq.mpr h)` 收尾。
  已在 [`Obstruction.lean`](../EvidenceLogic/Frontier/Obstruction.lean) §2.5 落地并复用。
  **等价路线**：中间函数/探针直接用**显式 λ 的 `PSet` 字面量**
  （`fun X Y => ⟨fun w => X.holds w ∧ Y.holds w⟩`），从源头绕开实例不透明性。
* **`PSet` 没有 `le_antisymm`**：集合层要得等式，用 `PSet.ext` ＋ 两条 `→`
  （或已有的 `pset_le_antisymm`）拼出来。
* **投影 `.holds` 形式的元素之前，先用 `Iff.rfl` 展开引理把它变成显式 `∧`／`→`**：
  `(f A B).holds w` 这种形式在**缺少期望类型**时（例如目标是 `False`）elaborator 不肯归约到
  `A.holds w ∧ B.holds w`，于是 `hc.1`／`.left` 一类投影会报"类型不符"。
  正解是先经展开引理（如 `notAndS_at : (notAndS A B).holds w ↔ (A.holds w → False) ∧ B.holds w`，
  `:= Iff.rfl`）拿到**显式形状**，再做 `.1`／`.2` 与应用——这样每一步都有明确类型。
  `SingleLayerFull.lean` 的 P₂／P₃／P₄ 就是照这条写的（一次通过）。
* **双重否定消去**：本工程无 `by_contra` 策略，用
  `theorem dne {P} (h : (P → False) → False) : P := Classical.byContradiction h` 自行补即可。
* **`#eval` 探针不要留在库模块里**：它会往构建日志打 `info` 输出（不是 warning，但污染输出）。
  集成时把 `#eval` 注释掉，并把实测结果写进注释（见 `Obstruction.lean` 末尾）。
* **索引族的归纳要用"强化消去器"**：索引含 `Kind.form k …`（对变量 `k` 是 stuck）时，
  方程风格的结构递归会退化成对 `Form` 索引的 `sizeOf` 良基序并报终止性失败；
  正解是把**指标写成变量**的谓词（如 `SuppInv : Form → Prop`）配 `Derivable₀.rec`／`Ev.rec`，
  递归由消去子自带的归纳假设给出，**不需要任何终止性证明**。
  需要依赖消去时（`h : Ev (Form.atom i ts ⊳ b)` 直接 `cases` 会失败），可用
  `revert h; generalize hφ : … = φ; intro h; cases h`，但该手法会打散递归变量、与结构递归不可兼用。
