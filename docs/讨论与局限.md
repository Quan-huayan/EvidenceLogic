> **导航**：如果只想看"现在缺什么"，直接跳到 **[第 7 节](#7-后续工作补充本次推进后的更新)**；
> 第 1–6 节是原始设计层面的局限（`⊢` 是语义定义的、完备性未证、第十节结论的强度、

> **一句话**：唯一实质前沿是 `TransferLemma`（未证、未被反驳）；另有五处分析被机器检查推翻或修正。

## 1. `⊢` 是语义定义的

定稿把 `⊢`（经典后承）当作给定的前提。本项目把它定义为"在所有基结构中有效"
（`Entails`，见 `EvidenceLogic/Model/Semantics.lean`），而**不是**先在 Lean 中实现
一套经典 Hilbert 演算再证明其完备性。

* 好处：自足、可判定地验证；代入与量词实例化等引理都能直接证明。
* 代价：S1／S2／E 的副作用条件带有语义色彩。
* 由于 `Entails` 包含全部经典一阶有效式（含代入、量词实例化、重言式、爆炸律），
  定稿需要的每一次 `⊢` 都能落实；但**不**声称 `Entails` 恰为一阶可推导关系
  （其间可能更强）。这一点在使用 `Entails` 作为副作用条件时需注意：
  例如 `Entails F1 F0` 因为量化**所有**基结构（原子解释任意）而**不成立**。

## 2. 完备性未证

本项目只证明了**可靠性**与**模型存在性**，没有证明"有效 ⟹ 可推导"。
障碍是实质性的：

* 模型类的关系是**语法索引**的：规范化模型需要把"命题"取为公式模 `⊣⊢` 的
  Lindenbaum 代数，而 `IsModel.s1` 等条件要求关系对**任意**命题（不只是可由
  公式表示者）都有定义；
* `f1`／`f2` 要求关系对**任意交**封闭，而 Lindenbaum 代数中公式族的下确界
  未必仍由某个公式表示。

因此"有效性是否恰等于可推导性"在本形式化中是**公开问题**，
不应与本文其他结论混同。

## 3. 第十节结论的强度：非有效性 vs 非可容许性

定稿第十节说这些命题"不能推出"。严格地有两种读法：

1. **非有效性**：相应蕴含式在模型类中不成立，故不可推导（作为公式）。
   本项目对**全部 10 条**给出这一结论，并直接得到不可推导性
   （`_not_valid` + `_not_derivable`）。
2. **非可容许性**：相应**规则**不可导出，即存在"前提可推导而结论不可推导"
   的实例。这更强。

本项目目前对「**拆合取支持者**」给出了完整的非可容许性证明
（`and_split_not_admissible`），其余条目只给出非有效性。

**特别提醒**：支持传递在**某些实例中其实是可容许的**——若中间环节是经典后承
（`b ⊢ c`），则 S2 直接给出 `a ⊳ c`。这正是定稿第七节自己承认的例外
（"不加，除非中间是经典后承"）。所以"支持传递不可推导"的准确含义是：
**作为规则模式它不成立**，而不是每个实例都推不出。

## 4. 语义为何长成这样（一条值得记录的观察）

若把 `⊳` 解释为朴素的"`X ≤ Y` 蕴含"、`⊲` 解释为"`X ⊓ Y = ⊥`"，
则支持传递会变成有效式，与定稿第十节冲突；而把关系做成**真值索引**
（`suppI : PSet → PSet → PSet`）又会让 P1 退化为平凡条件（见
[`设计说明.md`](设计说明.md) 第三节）。

于是本项目采取折中：**背书语义用语法索引关系**（保住 P1／P2 的实质内容），
**经典基语义用真值索引关系**（保住代入引理与 `⊢` 的经典性）。
两者由 `IsModel.classical` 连接。典范模型族中 `X = ⊤`（自相矛盾的支持者）
与 `⟦φ⟧ = ⊤`／`⟦φ⟧ = ⊥` 三个附加析取项，则是打破传递性、同时满足 R1 的
最小装置。

## 5. 未形式化的部分

* **函数符号与多元项**：`atom` 接受参数列表，已可表达多元谓词，
  但未引入函数符号；也没有 α-等价／de Bruijn 处理，代入用"可代入"条件
  `FreeFor` 处理捕获。
* **第八节的元层面表述**："非单调""非加性""不蕴涵真"是性质描述而非公式。
  本项目以可核查的定理与反模型给出实例：`Properties.supp_right_closure`、
  `Properties.supp_and_intro`、`Properties.supp_explosion`、
  `Properties.support_does_not_imply_truth`、`NonDerivable.not_truth_preserving`、
  `NonDerivable.s7_not_valid`。
* **"反驳有命题性和非命题性两类"**中"非命题性反驳不推出 `t ⊳ ¬φ`"属不可推导性，
  由第十节相应反模型体现。
* **非单调性**未形式化为定理模式（需要额外的"证据增删"结构），
  仅在本文件中作为设计说明记录。

## 6. 后续可做

1. 补完其余条目的**非可容许性**（需要为每条构造"前提可推导"的实例）；
2. 把经典基改为 Lean 内的 **Hilbert 演算**并证其相对于基语义的完备性，
   使 `⊢` 完全语法化；
3. 加入**函数符号**并处理 α-等价；
4. 尝试**部分完备性**：例如限制到不含 P1／P2 的片段，或对关系取
   "命题 = 公式模 `⊣⊢`" 的 Henkin 式语义。

## 7. 后续工作补充（本次推进后的更新）

**方法学观察（值得写下来）**：本项目多次出现"某条结论证不出来"，逐条追查后根因分三类：
①**技术性**（编码/透明度/终止性，可绕过）；②**陈述层面有缺口**（例如不变量不能对任意模型陈述）；
③**目标本身为假**（证不出来的真正原因是命题不成立）。
其中 ③ 至少出现 **3 次**且都被 Lean 拦下（`a⊓b = a⊓b' ⇒ a ≤ b`；`a⊔b = a⊔b' ⇒ b = b'`；
以及"从两个否定 A 的事实推出 `False`"）。
**教训**：卡住时先 `#check` 出精确目标、把命题写成可检查的形式，再判断是技术困难还是陈述问题——
"零 `sorry`、不许有未验证断言"这条纪律拦住的主要是**错的结论**，而不是好结果。

本节记录 1–6 节之后的进展与**新暴露的局限**，与 [`主要结果.md`](主要结果.md) 第六节、
[`证据语义解读.md`](证据语义解读.md) 配套阅读。

### 7.1 第十节规则级非可容许性：战果与残余

* 十二个子命题中**十个**已给出规则级非可容许性（`NonAdmissible.lean` ＋
  `NonDerivable.and_split_not_admissible`）。
* 残余两条是**支持传递**与 **S7**。它们**不是**"尚未尝试"，而是已知**反模型方法被堵死**：
  * `suppP_middle_eq_top`、`support_transitivity_middle_truth_top`、`countermodel_formula_truth_ne_top`
    给出**机器验证的必要条件**（反例处中间项真值必为 `⊤`、被支持式真值必 `≠ ⊤`）；
  * 唯一出路是 `TruthPropagation`（本工程**未证**），而它唯一未闭合的 `E`（"洞在顶层"）一支
    归约到第 2 节的完备性／相合性问题；
  * **无 E 片段**的版本是**定理**（`EFree.noE_supp_le` 等）：任何支持传递／S7 的见证，
    **至少有一个前提不存在无 E 的推导**；
  * 该结果已被**严格扩张**（`RestrictedE.lean`）：允许 `E`，只要求每次 `E` 的**源公式不含
    关系子公式**（`NoRel`），不变量仍在**一切典范框架**上成立
    （`supp_le₁_canon` ⇒ `transitivity_valid_canon₁`／`s7_valid_canon₁`）。
    于是缺口被精确缩小到：

    > **见证中至少有一个前提的推导在顶层用了 `E`，且该 `E` 的源公式含关系子公式**
    > （即"嵌套关系重写"）。
  * 该缺口已被**进一步定位**（[`Transfer.lean`](../EvidenceLogic/Frontier/Transfer.lean)）：转移引理
    「`(u ⊳ v) ⊣⊢ (u' ⊳ v')` 迫使分量在典范基上真值相等」在**分量不含关系子公式**时**已证**
    （`cequiv_rel_components_of_noRel`，投影基结构法）；而 `E` 的"洞在顶层"这一步的源公式
    **不必**是关系式（`holeAtTop_source_need_not_be_supp` 给出机器验证的实例：
    `φ := (⊤ ⊳ ⊤) ∧ ⊤` 可推导且 `⊣⊢ (⊤ ⊳ ⊤)`），故转移引理在那里**没有前提可用**。精确表述：

    > 缺口恰在 `E` 的"**洞在顶层、且源公式不是关系式**"那一支。
    > （源公式确实是关系式时转移可行：`holeAtTop_of_transferLemma`。）
  * **上述定位其后被修正**（[`Conditional.lean`](../EvidenceLogic/Frontier/Conditional.lean)）：那是
    "投影基 ＋ 转移引理"**这条技术路线**的边界，不是前沿本身。把不变量改成**模 `⊣⊢`** 的形式后，
    `E` 的"洞在顶层"**自动闭合**（`cequiv_plug` ＋ 归纳假设，**不需要任何相干性输入**），
    九条规则支则全部归结为 `TransferLemma`。于是全部剩余缺口**收敛到一条引理**：

    > **`TransferLemma`（`Transfer.lean`）⇒ `Derivable`（含 `E`，无片段限制）上的支持-蕴含不变量
    > ⇒ 支持传递／S7 的结论在一切典范框架中有效 ⇒ `TruthPropagation`。**

    该条件化链条已机器验证（`supp_le_of_cequiv_canon`、`supp_le_of_transferLemma_canon`、
    `transitivity_valid_canon_of_transferLemma`、`s7_valid_canon_of_transferLemma`）；
    其中 `TransferLemma` 本身**仍是假设**（本工程未证，也未被反驳）。
    **注意方向**：这是**充分**条件；必要性（`TruthPropagation ⇒ TransferLemma`）**未知**，
    且 `TransferLemma` 断言的是**逐分量真值等式**，看上去严格强于传播律。
    所以"反驳 `TransferLemma`"只会让现有唯一路线失效，**不**等于推翻上面那条判断。
  * **另有一条路线完全绕过 `TransferLemma`**（[`Model/Strict.lean`](../EvidenceLogic/Model/Strict.lean)
    ＋ [`Frontier/NoRelFragment.lean`](../EvidenceLogic/Frontier/NoRelFragment.lean)）：
    把定稿**拒绝**的朴素读法 `X ⊳ Y ⟺ X ≤ Y` 做成**第二个模型族**（`strict_isModel`，十三个字段逐一验证），
    于是 `Derivable.soundness` 直接给出**全量 `Derivable`（含任意 `E`）无条件**的支持-蕴含不变量
    （`strict_supp_le`——本工程第一条这样的结果）；再用"关系自由公式的真值与 `suppI`／`refutI` 无关"
    （`truth_noRel_congr`）把它搬到典范框架，得 `supp_le_canon_of_noRel`。
    与 `RestrictedE`／`Conditional` **互不包含**：这里不限制 `E`、也没有假设，代价是**分量必须 `NoRel`**。
    进一步沿两条前提**串联**（`strict_supp_le_trans`）得 `transitivity_le_canon_of_noRel`，
    **中间公式 `b` 可以任意**：
    由此两条障碍被收窄（**语法形状**）——支持传递的典范框架反模型**必须**让**结论的分量** `a` 或 `c`
    含关系子公式（`countermodel_needs_rel`），S7 则要求结论的两个分量之一含关系子公式
    （`s7_countermodel_needs_rel`）。
    这与本节第一条（**真值形状**：反例处 `⟦b⟧ = ⊤`）是**互相独立**的限制。
    再加上阈值族给出**第三条**（**跨模型**）：若中间公式 `b` 关系自由，则反例处
    **每一个**非典范阈值模型都迫使 `⟦c⟧_{th_U} = ⊤`
    （`canon_middle_noRel_supported_top_in_threshold`）——若 `c` 关系自由即与 `⟦c⟧_C ≠ ⊤` 矛盾。
    但**未攻下**残余两条：结论分量含关系子公式的一般情形**仍然**归约到 `TransferLemma`／第 2 节公开问题，
    且严格蕴含框架**验证的规则更多**（如支持传递本身），故它**不能**用来构造任何 N3 反例。
  * **第三条路线：阈值族**（[`Model/Threshold.lean`](../EvidenceLogic/Model/Threshold.lean)）：
    把 `suppP` 的 `X = ⊤` 换成**任意固定阈值** `U` 后**仍是模型**（`th_isModel`），
    于是对**每个** `U` 都有一条不变量 `th_supp_le`。其中 `U = ⊤` 时即典范框架的可靠性结论，
    别的 `U` 给出**不同**的约束（同一命门的两侧），故这是一族**互相独立**的必要条件；
    它同时是 §7.7 那条措辞修正的证据。
  * 注意该不变量**只能对典范框架陈述**：`M.truth φ ρ` 与
    `(Canon.base M.W M.atomRel).truth φ ρ` **不是定义性相等**，任意模型版的陈述即有缺口
    （见 [`设计说明.md`](设计说明.md) 第八节）。

### 7.2 `Prop` 与 `Type`：一个核层面的限制

* `Derivable : Form → Prop` 使推导**证明无关**；而 Lean 的核禁止从 `Prop` 大消去到 `Type`，
  因此 `Derivable → Ev`（[`Evidence.lean`](../EvidenceLogic/Analysis/Evidence.lean) 的 `Type` 值呈现）
  **不可定义**（实测 `recursor … can only eliminate into Prop`）。
* 后果：在 `Prop` 呈现下**无法**做正规形／inversion／可判定性这类"对证明做计算"的工作，
  故"`Derivable` 的正向刻画"在当前呈现下**连陈述都受限**（只能陈述 `Prop` 层的存在性，
  不能抽取被断言的对象）。要走到那一步，必须改用 `Type`／`Sort` 值的推导关系。

### 7.5 对第 4 节措辞的修正

第 4 节结尾说 `X = ⊤` 与 `⟦φ⟧ = ⊤`／`⟦φ⟧ = ⊥` 三个附加析取项是"最小装置"。
更精确的说法（`Structure.suppP_iff_le_or_top`、`Structure.refutP_iff_disjoint_or_top`）是：

* **支持侧本质 2 项**（`X ≤ Y ∨ X = ⊤`）、**反驳侧本质 3 项**（`X ⊓ Y = ⊥ ∨ X = ⊤ ∨ Y = ⊤`）；
  写出来的支持侧 `Y = ⊤` 与反驳侧 `Y = ⊥` 是**冗余**的。
* 各析取项的分工（`Disjuncts.disj_reduced_frame_not_model` 等，机器验证）：
  支持侧 `X = ⊤` 是**唯一**破坏传递性的装置；反驳侧 `Y = ⊤` 是 **P1（`kR = ⊲`）所需**（删去它框架不再是模型）。
  ——**"唯一装置"这一措辞已在 §7.7 修正。**

### 7.7 对「`X = ⊤` 是唯一破坏传递性的装置」这一措辞的修正

本节第 7.5 节的表格（以及 README 第 3 条）曾写：支持侧 `X = ⊤` 是**唯一**破坏传递性的装置。
第 7.6 节的**阈值族**给出机器验证的反例：把 `X = ⊤` 换成**任意**固定集合 `U`，

```
thSuppP U X Y := X ≤ Y ∨ X = U ∨ Y = ⊤
```

仍然是 `IsModel`（`th_isModel`，任意 `U`、任意 `W`、任意 `atomRel`），而
`thSuppP_not_transitive`（**零公理**，成立条件 `X ≤ U`、`X ≠ U`、`X ≰ Z`、`Z ≠ ⊤`）
说明**每一个** `U` 都能破坏传递性；`ThWitness.witness` 用 `Fin 3` 上的
`U = {0,1} ≠ ⊤` 给出具体见证。

准确的说法是：

> 破坏支持传递的装置不是 `⊤` 这个具体集合，而是**"支持者恰等于某个固定阈值"这一形状**
> （`U = ⊤` 时即 `Canon.suppP_not_transitive`，故那一条是该形状的一个特例）。

**为什么原措辞会出错**：`Structure.lean` 第六节讨论的是**典范判据 `suppP` 自身**——
在那一族里 `X = ⊤` 确实是唯一的。把"在 `suppP` 中唯一"读成"在一切模型族中唯一"是**过强的推广**；
阈值族正是把这个推广证伪的机器验证。**教训**（与方法学观察第 ③ 类同源）：
一条"唯一性"断言必须连同**它所量化的族**一起陈述，否则很容易在换族时变成假命题。

### 7.6 第二模型族与「设计取舍」的地位（`Model/Strict.lean`）

第 4 节与 `Canonical.lean` 开头都写过一句**设计理由**：

> 语义不能退化为朴素的 `X ≤ Y` 蕴含读法（否则支持传递将成为有效式）。

这句话现在**是定理**：把朴素读法做成

```
严格蕴含框架：M.supp X φ ρ := X ≤ ⟦φ⟧_base，   M.refut X φ ρ := X ⊓ ⟦φ⟧_base = ⊥ ∨ ⟦φ⟧_base = ⊤
```

之后 `strict_isModel` 证明它满足 `IsModel` 的全部十三个字段，而
`strict_transitivity_rule_valid` 证明在该框架中**支持传递的规则形式成立**。

三点必须分清：

1. **这不与 `NonAdmissible` 冲突**：那里十条 N3 的反例全部取自**典范框架**
   （`M3`／`M4` 都是 `Canon.frame`），而同一规则可以在一个模型里有效、在另一个模型里失效。
2. **它不解决前沿**：严格框架**验证的规则更多**（支持传递、S7、甚至拆合取支持者都有效），
   所以它**拿不到**任何 N3 反例；它的用处是**定位困难**：`suppP` 的析取项 `Y = ⊤`
   （`Disjuncts.lean` 指出它是唯一破坏传递性的装置）在严格框架里不存在，缺口随之消失。
3. **它给出了"同一个公理系统至少有两个模型族"这一事实**（`Canon.frame` 与 `strictFrame`），
   因此"哪一族才对"**不是逻辑问题**而是**设计取舍**：定稿选择 `suppP` 是为了让
   支持传递／S7 在语义上**失效**，从而与第十节的"推不出"一致。这是本工程第一条
   **把定稿的设计理由证明成定理**的结果（另一条平行的观察是反面：
   `Structure.suppP_not_transitive` 给出 `suppP` 本身不传递的具体反例）。

**第三族（本轮已机器验证，取代此前的"候选"）**：把 `X = ⊤` 换成**任意固定阈值** `U`（见
[`Model/Threshold.lean`](../EvidenceLogic/Model/Threshold.lean)）：

```
thSuppP U X Y := X ≤ Y ∨ X = U ∨ Y = ⊤        thRefutP U X Y := X ⊓ Y = ⊥ ∨ X = U ∨ Y = ⊤
```

`th_isModel` 对**任意** `U` 逐一验证十三个字段（**不**用可靠性反推），故它**不依赖任何前沿假设**；
`th_supp_le` 随之对**每个** `U` 给出一条不变量。三点观察：

* **`U = ⊤` 时它就是典范判据**（只差一个冗余的 `Y = ⊥`），而别的 `U` 给出**不同**的约束
  ——这是一族**互相独立**的必要条件，不是同一条定理的重述；
* **破坏传递性的装置是"阈值形状"而不是 `⊤`**：`thSuppP_not_transitive`（**零公理**）对任意 `U`
  给出非传递见证，`ThWitness.witness` 给出 `U = {0,1} ≠ ⊤` 的具体反例（只需 `propext`）。
  这是对 §7.7 那条措辞的**机器验证的修正**；
* **但它同样不能造反例**：与 `strictFrame` 一样，本族中可推导的结论全都有效，
  `thSuppP` 不传递**只说明这个关系不是预序**。要成为 N3 反例仍需**可推导的**两个前提——
  而那正是尚未解决的部分（拦路的问题与前沿**同构**：需要 `Derivable (b ⊳ c)` 且
  `⟦b⟧ = U` 而 `⟦c⟧` 不含某个不在 `U` 里的集合；若 `c` 关系自由，`strict_supp_le`
  立刻给出 `U ≤ ⟦c⟧` 而**封死**反例——所以反例必须让**结论分量**含关系子公式，
  与 §7.1 新增的语法必要条件 `countermodel_needs_rel` 一致）。
